# research_log — staying current, on the record

An automated research routine keeps the project current on developments relevant to
**human meaning in the post-AI / post-labour era**, and commits its findings here daily so the
repo is the durable record (Claude's memory resets; the repo does not).

## Files
- **`ROUTINE_DAILY.md`** — the prompt for the daily scan.
- **`ROUTINE_WEEKLY.md`** — the prompt for the weekly synthesis.
- **`SETUP.md`** — how to schedule them (native web routine, or GitHub Actions cron).
- **`daily/YYYY-MM-DD.md`** — daily scan outputs (curated; "nothing substantive" days are fine).
- **`weekly/YYYY-Www.md`** — weekly digests; these feed the permanent files.

## How it compounds
Daily scans are the staging area. The **weekly digest** is where value accumulates: genuine
🟢 empirical anchors get promoted into `../evidence_base.md`, article sparks into
`../idea_pool.md`, recurring patterns into `../concepts.md`. Over time this turns "staying
informed" into a growing, citable asset that feeds the Medium writing.

## Discipline
Both prompts enforce the project's honesty rules: every item tagged 🟢 empirical /
🟡 analogical / 🔴 design; cite what sources show, not headlines; never inflate certainty;
quiet days/weeks are reported as such, not padded. The aim is a trustworthy knowledge base,
not the appearance of activity.
